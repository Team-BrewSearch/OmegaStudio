.trm models (GameCube and PS2) and .psp models (PSP) are RenderWare files with Torus wrappers. A .trm is one RW struct chunk followed by numAtomics RpAtomic chunks and nothing else. The struct's payload begins with a 4-byte endian marker (BA DA 55 35 on GameCube, 35 55 DA BA on PS2) that the chunk size does not count, so the atomics start at 0x10 + size.

Arrays (in this order)

  • Instances: {u16 frame, u16 atomic, u32 ARGB colour}. A colour of 0 becomes the default 0xFEFFFFFF; any other is forced opaque (| 0xFF000000), which shows the word is ARGB.
  • Name hashes: {u32 hash, u32 frame}
  • Named instances: {u32 name hash, u32 instance index}
  • Parents: s16, always lower than the frame's own index
  • Local matrices: RenderWare row-vector 4x4 floats, translation in the last row. A frame's world matrix is its local times its parent's world.
  • The 0x54-byte records (none shipped)
  • The second blob (one GameCube file has 3,242 bytes whose contents are not decoded)
  • The animation blob

The header size equals the sum of these exactly. The atomic's own RW struct holds stale pointers and is not used. Instancing builds one 0x34-byte runtime record per instance, taking the atomic from the instance's u16 at +2 and the frame's world matrix from the u16 at +0.

Animation

The animation blob holds, in order: animations (32 bytes), tracks (16), keys (8), events (8), then the key data. Counts are header +0x10, +0x12, +0x14 and +0x16. Relocation points each animation at the key data. An animation is {u32 name hash, u32 track count, f32 duration in seconds, u32 0, u16, u16 event count, u32 first track, u32 first event, key data}. A track is {u32 bone name hash, u32 key count, u32 type, u32 first key}, the hash being the one in the model's frame name table. A key is {f32 time in seconds, u32 byte offset into the key data}, and an event is {f32 time, u32 id}. PSP holds the same records with pointers in place of indices. Key data is little-endian on every platform, GameCube included.

The track type is a mask, and a key holds its parts in this order: rotation (4, a quaternion x, y, z, w as s16 over 16384), translation (2, three floats), uniform scale (1, a float). A key builds the local matrix scale x rotation x translation in RenderWare's row-vector order; between keys the rotation is slerped and the rest interpolated linearly. Frames without a track keep their bind local. Rotation keys are normalized at decode. All 804 GameCube, 811 PS2 and 838 PSP clips pose without a non-finite value.

glTF export carries every clip losslessly. Rigid atomics in a rig become one-bone skins of their frame, so clips move them. The skin's own inverse bind matrices are exported, including the 27 that disagree with the frame hierarchy. Key parts go out as the decoded translation, rotation and scale. Clip extras hold the anim hash, exact duration, flags and events. Reimporting every model on all six discs and posing each clip under glTF rules matches the viewer's pose to within 6e-6 of model size.

GameCube native geometry

Geometry flags always include rpGEOMETRYNATIVE; the binmesh (0x50E) holds no indices, only per mesh {u32 index count, u32 material}. The native data struct (0x510) begins with three little-endian words: platform 6, header size, data size. The header is big-endian: two words, the attribute count, then per attribute {u32 offset, u8 GX attribute, u8 stride, u8 index type, u8 0}, then per binmesh mesh {u32 display list offset, u32 length}. Offsets count from the end of the header. Attributes seen are position (9, three floats), normal (10, three floats), colour 0 (11, RGBA8), texture 0 and 1 (13 and 14, two floats); index type 2 is 8-bit and 3 is 16-bit. A display list is GX primitives, opcode 0x98 (triangle strip) in every shipped file, a big-endian vertex count, and one index per attribute per vertex in attribute order; it ends exactly at its stated length. GX strips are clockwise-front, so the host's triangles are emitted reversed.

Transparency

Transparency follows RenderWare's rule of blending whenever the texture raster or the prelight colours carry alpha: a texture whose alpha is only 0 or 255 is drawn as a cutout, one with partial alpha is blended, and so is any mesh whose vertex alpha falls below 254. No shipped vertex colour has alpha 255; 254 is the exporter's full opacity (on PS2 it is twice 0x7F).

In OmegaStudio

GameCube and PS2 .trm and PSP .psp models render with their textures and play every animation they carry, and the animations export with the model to glTF. A model's atomics are placed by the frames its instance table names, so a level shows every placed prop. Skinned characters carry their frame hierarchy as a skeleton with per-vertex bones and weights. A texture is looked up by name in the .tex of the model's own level folder, then gcn/textures/structure, then any other dictionary in the pack. Models with no atomics (camera and object animation files) show only their details. Models with no textures still render untextured.
